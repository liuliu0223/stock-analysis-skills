# 三接口合成决策逻辑

## 一、合成规则详解

### 1.1 判定矩阵

```
              技术面
           PASS  |  COND  | FAIL
资金面  +-------+-------+-------+
 PASS    | STRONG| CONDP |  FAIL |
        | PASS  | PASS  |       |
  +-----+-------+-------+-------+
 COND    | CONDP | CONDP |  FAIL |
        | PASS  | PASS  |       |
  +-----+-------+-------+-------+
  WEAK   | CONDP | CONDP |  FAIL |
        | PASS  | PASS  |       |
  +-----+-------+-------+-------+
  FAIL   |  FAIL |  FAIL |  FAIL |
        +-------+-------+-------+

安全垫修饰：
  THICK:  不改变合成结论（但强化信心）
  MODERATE: 正常
  THIN:   STRONG_PASS → CONDITIONAL_PASS（降一级）
  NO_MARGIN: 一票否决 → FAIL
```

### 1.2 一票否决清单

| 否决项 | 来源 | 触发条件 | 处理 |
|---|---|---|---|
| V1 窗口不足 | 资金面 L0 | 任一窗口覆盖 < 80% | 整体 → INSUFFICIENT_DATA |
| V2 无资金 | 资金面 | flow_grade = FAIL | 整体 → FAIL |
| V3 趋势空头 | 技术面 L0 | trend_state = BEAR_STRUCTURE | 整体 → FAIL |
| V4 信号假 | 技术面 L1 | 确认项数 = 0 | 整体 → FAIL |
| V5 无安全垫 | 安全垫 | safety_grade = NO_MARGIN | 整体 → FAIL |
| V6 PIT 违规 | 全局 | 发现使用未来数据 | 整体 → INVALID（分析作废） |

> **关键**：一票否决不打分，直接结论。否决项越多，越说明这个标的不该出现在候选池中。

## 二、仓位计算公式

### 2.1 基础公式

```
实际仓位(%) = 风险预算(%) / (止损距离(%) × ATR倍数)
```

### 2.2 参数定义

| 参数 | 默认值 | 说明 |
|---|---|---|
| **风险预算** | 账户规模的 1%~2% | 单笔交易最大可接受亏损 |
| **止损距离** | 1.5 × ATR(14) | 基于 14 日真实波幅的 1.5 倍 |
| **ATR 倍数** | 1.5 | 可根据风险偏好调整 |
| **合成等级系数** | STRONG_PASS=1.0, COND=0.5, WEAK=0.3 | 基于三接口合成结论 |

### 2.3 示例

```
账户规模: 100万元
风险预算: 1% = 1万元
标的 ATR(14): 3.2%
止损距离: 1.5 × 3.2% = 4.8%
合成等级: CONDITIONAL_PASS (系数 0.5)

基础仓位 = 10%
实际仓位 = 10% × 0.5 × (3.0% / 3.2%) = 4.7%
对应金额 = 100万 × 4.7% = 4.7万元
止损价 = 现价 × (1 - 4.8%)
```

### 2.4 行业集中度限制

| 行业集中度 | 上限 | 说明 |
|---|---|---|
| 单行业持仓 | ≤ 总仓位 30% | 防止行业黑天鹅 |
| 单票持仓 | ≤ 总仓位 10% | 防止个股黑天鹅 |
| 全部持仓 | ≤ 80% | 保留现金缓冲 |

## 三、行业中性化

### 3.1 为什么需要中性化

原框架六大缺陷中的"行业 beta 未中性化"问题：

- 整个板块涨 5% 时，个股涨 3% → 看似"弱势"，但可能相对板块表现优异
- 必须**先减行业中位数，再做判定**

### 3.2 中性化计算方法

**资金面中性化**：

```
adjusted_main_net_rate = individual_main_net_rate - sector_median_main_net_rate
```

判定使用 `adjusted_main_net_rate` 替代原始值。

**技术面中性化**：

```
adjusted_return_5d = individual_return_5d - sector_median_return_5d
```

仅在 L0 趋势分层中考虑（即个股相对板块的超额收益），不影响原始趋势判定。

### 3.3 中性化判定调整

| 条件 | 原判定 | 中性化后 |
|---|---|---|
| 个股涨 3%，板块涨 5% | 看起来不错 | 调整后为 -2%，实质弱势 |
| 个股跌 1%，板块跌 3% | 看起来差 | 调整后为 +2%，实质跑赢 |
| 个股涨 0.5%，板块跌 0.5% | 涨幅小 | 调整后为 +1%，实质强势 |

> **注意**：中性化只用于 L2 量级门槛的**辅助参考**，不作为 L1 通过条件。
> 因为板块中位数本身也有噪声，过度依赖会导致"板块强才敢做多"的从众逻辑。

## 四、PIT 约束实施细则

### 4.1 Point-in-Time 原则

**核心规则**：所有指标只能使用 **T 日收盘时已知**的数据。任何使用 T+1 或之后才披露的数据都属于前瞻偏差。

### 4.2 财报数据的 PIT 规则

| 数据类型 | 可用时刻 | 原因 |
|---|---|---|
| 财报数值 | **公告日**之后 | 公告前不可知 |
| 财报数值 | 报告期结束 | ❌ 不可用（前瞻性） |
| 分析师一致预期 | 发布时刻之后 | 同上 |
| 资金流 | 收盘后 | ✅ 当日收盘统计完成即可 |
| K 线数据 | 收盘后 | ✅ 当日交易完成后即可 |

### 4.3 PIT 校验清单

```python
def pit_check(code, target_date, data_dict):
    """
    校验数据是否满足 PIT 约束
    data_dict: {'PE_TTM': ..., 'fund_flow': ..., 'kline': ..., ...}
    """
    violations = []
    
    for field, value in data_dict.items():
        if field in ('PE_TTM', 'PB', 'dividend_yield'):
            # 财报类指标：检查公告日是否在 target_date 之前
            if field.get('announcement_date') > target_date:
                violations.append(f"{field}: 公告日 {field['announcement_date']} 晚于分析日 {target_date}")
        
        if field in ('net_profit_yoy', 'gross_margin_trend'):
            # 财报：检查报告期 + 公告日
            if field.get('report_end_date') > target_date or field.get('announcement_date') > target_date:
                violations.append(f"{field}: 数据不可知")
    
    return violations
```

### 4.4 常见 PIT 陷阱

| 陷阱 | 表现 | 处理 |
|---|---|---|
| 用年报预期当当期数据 | 1月用年报数据（4月才公告） | 只取已公告数据 |
| 用次日开盘价做当日指标 | 次日开盘价受隔夜消息影响 | 只用 T 日收盘数据 |
| 季报窗口期偏差 | 季报发布窗口 1~4 个月 | 窗口标注"数据截止日" |

## 五、已知缺陷的缓解方案

### 5.1 过拟合

**问题**：阈值（1.5%、1.0%、30%等）可能在历史数据上拟合良好，但在样本外失效。

**缓解**：

| 缓解措施 | 说明 |
|---|---|
| **跨周期验证** | 阈值至少在 2022、2023、2024、2025 四个年份各验证一次 |
| **阈值敏感性分析** | 阈值 ±20% 范围内结论是否稳定 |
| **保留中间状态** | CONDITIONAL_PASS 本身就是缓冲 |

### 5.2 缺乏交叉验证

**问题**：原框架各接口独立判定，缺乏接口间的交叉检查。

**缓解**：本框架通过以下交叉检查解决：

| 交叉检查 | 逻辑 |
|---|---|
| 资金 PASS + 技术 FAIL | 资金在流入但技术面已破位 → 可能是主力对倒出货 |
| 技术 PASS + 安全垫 NO_MARGIN | 信号好但没有下行保护 → 高风险高波动标的 |
| 安全垫 THICK + 资金 FAIL | 价值好但资金没进来 → 可能已被市场遗忘 |

### 5.3 缺乏基准比较

**问题**：原框架没有与基准（如沪深 300）的比较。

**缓解**：在合成判定中引入相对收益基准：

```
if individual_return > benchmark_return * 1.5:
    grade_upgrade = True  # 可考虑 PASS 升级
elif individual_return < benchmark_return * 0.5:
    grade_downgrade = True  # 可考虑降级
```

### 5.4 仓位建议无风险预算锚定

**问题**：原框架只给"可加仓""可建仓"等定性建议。

**缓解**：本框架提供定量仓位公式：

```
实际仓位 = 风险预算 / (止损距离 × ATR倍数) × 合成系数
```

## 六、边界场景处理

### 6.1 ST/退市风险股

| 条件 | 处理 |
|---|---|
| ST 股 | 所有判定阈值 × 0.5（降低期望） |
| 连续亏损 | 安全垫 L4 直接 -1 |
| 净资产为负 | 安全垫 L4 -1，L1 估值无效 |

### 6.2 新股/次新股

| 条件 | 处理 |
|---|---|
| 上市不足 60 日 | 资金面 L0 不合格 → INSUFFICIENT_DATA |
| 上市不足 120 日 | 技术面 MA120 无法计算 → 跳过 MA120 判定 |
| 上市不足 250 日 | 安全垫数据可能不完整 → 降级标记 CONDITIONAL |

### 6.3 停牌股

| 条件 | 处理 |
|---|---|
| T 日停牌 | 不执行分析，标记 `SUSPENDED` |
| 停牌超过 5 日 | 复牌后第一天不做分析（数据不可比） |
| 复牌后第 2 日 | 正常分析，但标注"复牌后第 2 日" |

### 6.4 数据缺失场景

| 场景 | 处理 |
|---|---|
| 腾讯行情 API 不可用 | 标记 `DATA_UNAVAILABLE`，不执行分析 |
| 单个字段缺失 | 跳过该字段对应的判定项，得分记 0 |
| 3 个以上字段缺失 | 整体 → INSUFFICIENT_DATA |

## 七、快速检查清单

在输出最终结论前，逐项确认：

### 数据检查
- [ ] 所有窗口覆盖 ≥ 80%？
- [ ] 无 PIT 违规？
- [ ] 行业中位数已填入（或跳过 L1 估值）？

### 判定检查
- [ ] 资金面 L0~L4 逐项判定？
- [ ] 技术面 L0~L2 逐项判定？
- [ ] 安全垫 L1~L4 逐项判定？

### 合成检查
- [ ] 一票否决项已检查？
- [ ] 降级标记已应用？
- [ ] 仓位公式已计算？

### 输出检查
- [ ] 结论有对应等级（PASS/COND/FAIL）？
- [ ] 每个等级有对应判定依据？
- [ ] 警示信息已包含？
