# 股票三领域分析

## 定位

把股票分析从"定性叙事"升级为**三个独立量化接口的分层判定**。

三个接口各司其职、互不替代：

| 接口 | 回答的问题 | 关键指标 | 输出等级 |
|---|---|---|---|
| **资金面** (`fund_flow_interface`) | 资金流入是否跨周期一致、相对板块稀缺、结构质量高？ | 净流入率、板块排名、大单/中单结构 | PASS / WEAK / FAIL / INSUFFICIENT_DATA |
| **技术面** (`technical_interface`) | 趋势结构是否支撑？信号是否有量能+方向+位置三重确认？ | 趋势状态、确认系数、ATR% | PASS / CONDITIONAL_PASS / FAIL |
| **安全垫** (`safety_margin_interface`) | 判断错误时下行保护有多少？ | PE/股息率/筹码/盈利质量 | THICK / MODERATE / THIN / NO_MARGIN |

**一句话**：安全垫衡量"看错了亏多少"，资金面衡量"有没有钱进来"，技术面衡量"信号是不是真的"。三者不是"只要有一个好就行"，而是按合成规则综合判定。

---

## 何时使用

| 用户说 | 适用场景 | 前置条件 |
|---|---|---|
| "这个票三验怎么样" | 单股三维度分析 | 给出股票代码 |
| "帮我筛符合条件的票" | 选股 | 给出筛选条件或自选池 |
| "三维度分析 XXX" | 深度个股评估 | 给出代码 |
| "安全垫够不够" | 仅安全垫接口 | 给出代码 |
| "技术面过没过" | 仅技术面接口 | 给出代码+日K数据 |
| "资金结构怎么样" | 仅资金面接口 | 给出代码+资金流数据 |

**不适用**：
- 已有资金结构盯盘判定的标的（S1-S6 已覆盖资金面功能，本接口提供的是更严格的量化判定）
- 大盘/板块层面判断（走"每日复盘"技能）
- 建仓下单决策（走"建仓确认"技能）
- 持仓股日常盯盘（走"资金结构盯盘"技能）

## 与其他技能的分工

| 技能 | 负责 | 输出 |
|---|---|---|
| **本技能** | 三接口独立判定 + 合成决策 | 分层等级 + 合成结论 |
| `资金结构盯盘` | S1-S6 状态机（盘后快速扫描） | 状态码 + 分数 |
| `建仓确认` | 五验确认（下单前的交叉验证） | 放行/否决 |
| `每日复盘` | 大盘水位 + 板块分析 | 大盘/板块结论 |
| `钱来-agent` | 全流程自动决策 | 交易建议 |

**本技能是三维度分析的基础设施，其他技能在其之上做具体执行。**

---

## 核心原则

| # | 原则 | 推论 |
|---|---|---|
| 1 | **三层判定替代二元判定** | PASS / CONDITIONAL_PASS / WEAK / FAIL，中间状态保留信息量 |
| 2 | **所有阈值从数据推导** | 净流入率门槛、排名百分位、确认权重须样本外验证 |
| 3 | **强制 PIT 约束** | 指标只使用 T 日收盘时已知数据，财报以公告日为准 |
| 4 | **安全垫与多头逻辑分离** | 安全垫只回答"下行保护有多少"，不回答"上涨空间有多大" |
| 5 | **行业中性化** | 资金面和涨幅信号先减行业中位数，再做判定 |
| 6 | **仓位是风险预算的函数** | `仓位 = 风险预算% / (止损距离% × ATR倍数)` |

## 一、资金面接口 (`fund_flow_interface`)

### 1.1 接口定义

```
FUND_FLOW_SCREEN(code, sector, lookback_windows=[3, 5, 10, 20])
```

**输入字段**（逐日取数，PIT 约束：以 T 日收盘后已披露数据为准）

| 字段 | 含义 | 必需 |
|---|---|---|
| `main_net_flow` | 当日主力净流入额 | ✅ |
| `super_large_net` | 超大单净流入 | ✅ |
| `large_net` | 大单净流入 | ✅ |
| `total_amount` | 当日总成交额 | ✅ |
| `float_market_cap` | 流通市值 | ✅ |
| `sector_main_flow` | 所属板块当日主力净流入 | 板块穿透必需 |

**派生字段**

| 字段 | 计算 | 说明 |
|---|---|---|
| `main_net_rate_Nd` | N 日累计主力净流入 / N 日累计成交额 × 100% | **核心量级指标**，消除市值偏差 |
| `main_rank_in_sector` | 板块内按 `main_net_rate_5d` 降序排名 | 排名百分位 |
| `persistence_score` | 窗口内净流入为正的天数 / N | 连续性评分 |

### 1.2 判定逻辑（五层，L0→L4）

**L0 — 窗口完整性校验（硬门槛）**

任一窗口的实际覆盖天数 < 窗口长度的 80%，该窗口信号失效，整条记录标记为 **INSUFFICIENT_DATA**，不进入评分。

> 例：10 日窗口实际只有 6 天数据（6/10=60% < 80%），`+32.6 亿`累计值无可比性。

**L1 — 多周期方向一致性（必要条件）**

要求 3日、5日、10日三个窗口的 `main_net_rate` **同时为正**，且 20日窗口 `main_net_rate ≥ 0`。

> 替换原框架"全正"只看绝对金额的缺陷，改为净流入率消除市值规模偏差。

**L2 — 量级门槛（区分"微正"与"显著"）**

| 等级 | 条件 |
|---|---|
| **PASS** | `main_net_rate_5d ≥ 1.5%` 且 `main_net_rate_10d ≥ 1.0%` |
| **WEAK** | 满足 L1 但低于上述阈值（净流入率 < 1.5%，视为噪声级别） |
| **FAIL** | 任一窗口 `main_net_rate` 为负（不满足 L1） |

**L3 — 板块相对稀缺性（排名门槛）**

`main_rank_in_sector ≤ 板块成分股数量 × 10%`（或前 5 名，取更严格者）。

> 原框架"第 4 名"是有效信号，但需转化为可执行的排名百分位门槛。

**L4 — 资金结构质量（加分项，非硬条件）**

| 信号 | 条件 | 判定 |
|---|---|---|
| **机构吸筹** | 超大单+大单净流入 > 0 且 中单/小单合计净流出 | 结构加分 → 维持 PASS |
| **散户接盘** | 超大单净流出 且 小单净流入 | 结构扣分 → PASS 降为 WEAK |
| **中性** | 不满足以上任一 | 不加分不扣分 |

### 1.3 输出结构

```json
{
  "code": "600036",
  "flow_grade": "PASS",
  "main_net_rate_3d": 0.42,
  "main_net_rate_5d": 1.87,
  "main_net_rate_10d": 2.31,
  "main_net_rate_20d": 0.95,
  "sector_rank_pct": 0.03,
  "structure_flag": "INSTITUTIONAL_ACCUMULATION",
  "persistence_score_10d": 0.8,
  "note": "20日净流入率显著低于10日，中期资金持续性存疑"
}
```

### 1.4 常见陷阱

| 陷阱 | 表现 | 处理 |
|---|---|---|
| 20日 > 10日流入更多 | 前10日之外的10个交易日合计净流出约19亿 | 标注警示，20d 远弱于 10d 说明流入在减速 |
| 绝对金额大但 Rate 为 0.1% | 大盘股流通市值太大，Rate 被稀释 | 优先看 Rate，不看绝对金额 |
| 板块成分股太少 | 前5名门槛与10%门槛一样 | 取更严格者 |

## 二、技术面接口 (`technical_interface`)

### 2.1 接口定义

```
TECHNICAL_SCREEN(code, kline_data, confirm_window=3)
```

**输入字段**：日 K 线（至少 260 个交易日），字段：`open, high, low, close, volume, amount`。
所有指标仅使用截至 T 日已收盘数据计算，**禁止使用 T 日之后的任何数据**（PIT 约束）。

### 2.2 判定逻辑（四层，L0→L3）

**L0 — 趋势结构分层（新增，原框架缺失）**

首先判定中长期趋势状态，而非直接进入短期信号：

| 状态 | 条件 | 信号折扣 |
|---|---|---|
| **BULL_ALIGNED** | `close > MA60` 且 `close > MA120` | × 1.0（无折扣） |
| **SHORT_REPAIR** | `close > MA20/MA5/MA10`，但 `close < MA60` | × 0.7（天然折价） |
| **BEAR_STRUCTURE** | `close < MA20` 且 `close < MA60` | **直接 FAIL** |

> 短期均线修复 + 中长期空头排列 = 信号天然只能给 70% 权重。

**L1 — 核心信号确认（三重确认机制）**

单一金叉不构成通过。每个金叉/死叉需要三项独立确认才给满分：

| 确认维度 | 条件 | 权重 |
|---|---|---|
| **量能确认** | 信号日成交量 > 20日均量 × 1.2 | 40% |
| **趋势方向确认** | 信号方向与 MA20 斜率方向一致 | 30% |
| **价格位置确认** | 信号发生时价格未处于 BOLL 上轨外侧或 RSI > 75 | 30% |

**确认项数 → 信号系数**：

| 确认项数 | 信号系数 | 说明 |
|---|---|---|
| 3 项 | 1.0 | 满分确认 |
| 2 项 | 0.7 | 部分确认 |
| 1 项 | 0.5 | 弱确认 |
| 0 项 | 0.3 | 疑似假信号 |

> MACD 零轴下方金叉本身是弱信号，需量能和趋势确认补偿。原框架未做此校验。

**L2 — 超买超卖过滤（保留原逻辑）**

硬性排除条件：`RSI6 < 70` 且 `KDJ_J < 80`。不满足 → 信号系数 × 0.5。

**L3 — 波动率与仓位适配（新增）**

输出 `ATR(14)` 及 `ATR/close` 比率。波动率越高的标的，同等信号下建议仓位应越低。

```
仓位 = 基础仓位 × (目标波动率 / 标的 ATR%)
```

### 2.3 判定树

```
L0 趋势结构:
  BEAR_STRUCTURE  → 直接 FAIL（无折扣机会）
  SHORT_REPAIR    → 进入 L1，后续分数 × 0.7
  BULL_ALIGNED    → 进入 L1，无折扣

L1 三重确认:
  3/3 确认 → 系数 1.0
  2/3 确认 → 系数 0.7 → CONDITIONAL_PASS
  1/3 确认 → 系数 0.5 → WEAK
  0/3 确认 → 系数 0.3 → FAIL（疑似假信号）

L2 超买过滤:
  RSI > 70 或 KDJ_J > 80 → 系数 × 0.5

合成:
  最终分数 = raw_signal_score × 趋势折扣 × 确认系数 × (L2惩罚)
  ≥ 0.7  → PASS
  0.4~0.7 → CONDITIONAL_PASS
  < 0.4   → FAIL
```

### 2.4 输出结构

```json
{
  "code": "600036",
  "trend_state": "SHORT_REPAIR",
  "trend_discount": 0.7,
  "raw_signal_score": 0.85,
  "confirmed_signal_score": 0.60,
  "technical_grade": "CONDITIONAL_PASS",
  "confirmations": {
    "volume_confirmed": false,
    "trend_direction_confirmed": false,
    "price_position_confirmed": true
  },
  "rsi6": 58.3,
  "kdj_j": 65.2,
  "atr_pct": 3.2,
  "suggested_stop_loss": "止损距离 = 1.5 × ATR(14)",
  "note": "MACD零轴下方金叉，量能未确认，信号系数0.5；趋势结构为短期修复，整体折价至0.60"
}
```

## 三、安全垫接口 (`safety_margin_interface`)

### 3.1 接口定义

```
SAFETY_MARGIN_SCREEN(code, industry, financial_data, chip_data)
```

**输入字段**

| 维度 | 字段 | 用途 |
|---|---|---|
| 估值 | `PE_TTM`, `PE_industry_median`, `PB` | 相对估值锚 |
| 股息 | `dividend_yield` | 现金流安全垫底线 |
| 筹码 | `avg_cost`, `profit_ratio`, `close` | 套牢盘压力与下行支撑 |
| 盈利质量 | `net_profit_yoy`, `gross_margin_trend` | 基本面是否在恶化 |
| 预期安全垫 | `consensus_net_profit_TTM` | 一致预期偏离度（可选） |

### 3.2 判定逻辑（五档，L1→L5）

**L1 — 估值安全垫**

| 条件 | 得分 |
|---|---|
| `PE_TTM < PE_industry_median × 0.8`（折价 > 20%） | **+1** |
| `0.8 ≤ PE_TTM / PE_industry_median < 1.2`（持平） | **0** |
| `PE_TTM / PE_industry_median ≥ 1.5`（溢价 ≥ 50%） | **-1** |
| 其他溢价区间 | **-0.5** |

> 远期估值不能作为当期安全垫。只用于说明"如果增长兑现，估值压力会缓解"。

**L2 — 股息与现金流安全垫**

| 条件 | 得分 |
|---|---|
| `dividend_yield ≥ 3%`（价值型底线） | **+1** |
| `1% ≤ dividend_yield < 3%` | **0** |
| `dividend_yield < 1%` | **-1** |

> 行业特征（如"半导体设备股通常低股息"）可以解释原因，不能改变安全垫缺失的事实。

**L3 — 筹码安全垫**

| 条件 | 得分 |
|---|---|
| `profit_ratio > 60%` 且 `close > avg_cost`（上方无套牢压制） | **+1** |
| `40% ≤ profit_ratio ≤ 60%` | **0** |
| `profit_ratio < 30%` 且 `close < avg_cost × 0.9`（获利盘少且价格低于筹码均价10%+） | **-1** |
| 其他 | **-0.5** |

**L4 — 盈利质量安全垫（新增，关键）**

| 条件 | 得分 |
|---|---|
| `net_profit_yoy > 10%` 且 `gross_margin_trend` 为上升或持平 | **+1** |
| `net_profit_yoy > 0`（正增长但不高） | **0** |
| `net_profit_yoy < 0` 且 `gross_margin_trend` 下行（增收不增利） | **-1** |
| `net_profit_yoy` 在 -10%~0 之间 | **-0.5** |

> 这是最关键的一档：如果"成长"本身在减速，远期估值消化逻辑的根基就在松动。

**L5 — 预期利润安全垫（可选加分项）**

一致预期净利润 TTM 处于历史均值 +1σ 以上 → **+0.5**。
此因子仅用于加分，不改变 L1-L4 的硬性判定。

### 3.3 合成规则

将 L1—L4 得分加总（范围 -4 到 +4）：

| 总分 | 等级 | 含义 |
|---|---|---|
| **≥ 2** | **THICK** | 数值安全垫充足 |
| **0 ~ 1** | **MODERATE** | 有一定缓冲，但不充裕 |
| **-1 ~ -2** | **THIN** | 安全垫薄弱，仅适合小仓位试错 |
| **≤ -3** | **NO_MARGIN** | 无量化安全垫，不应作为"通过"项 |

> **关键**：安全垫衡量的是"判断错误时你亏多少"，不是"逻辑正确时你能赚多少"。
> 逻辑护城河是多头逻辑，不属于安全垫。

### 3.4 输出结构

```json
{
  "code": "600036",
  "safety_grade": "THICK",
  "l1_valuation": -0.5,
  "l2_dividend": 1.0,
  "l3_chip": 0,
  "l4_earnings": 0,
  "l5_consensus": 0.5,
  "total_score": 1.0,
  "note": "PE略高于行业中位数但股息率高(4.7%)，盈利稳定"
}
```

## 四、三接口合成与决策

### 4.1 合成逻辑

三接口独立判定后，按以下规则合成最终结论：

**合成判定表**

| 资金面 | 技术面 | 安全垫 | 合成结论 | 含义 |
|---|---|---|---|---|
| PASS | PASS | THICK/MODERATE | **STRONG_PASS** | 三维度共振，可重点配置 |
| PASS | CONDITIONAL_PASS | MODERATE | **CONDITIONAL_PASS** | 可小仓位试错 |
| WEAK | PASS | THICK | **WEAK_PASS** | 资金面信号弱，但其他维度高 |
| PASS | FAIL | 任意 | **FAIL** | 技术面硬否决 |
| FAIL | 任意 | 任意 | **FAIL** | 资金面无信号 |
| 任意 | 任意 | NO_MARGIN | **NO_MARGIN** | 无下行保护，不构成"通过" |
| 任意 | BEAR_STRUCTURE | 任意 | **FAIL** | 趋势硬否决 |

**一票否决项（任一触发 → FAIL）**

| 否决项 | 来源 | 条件 |
|---|---|---|
| 窗口数据不足 | 资金面 L0 | 任一窗口覆盖 < 80% |
| 无资金信号 | 资金面 | `flow_grade` = FAIL |
| 趋势空头 | 技术面 | `trend_state` = BEAR_STRUCTURE |
| 信号疑似假 | 技术面 | 确认项数 = 0 |
| 无安全垫 | 安全垫 | `safety_grade` = NO_MARGIN |

### 4.2 仓位建议公式

```
基础仓位 = 10%（单票上限）
风险预算 = 账户规模的 1%~2%
实际仓位 = 基础仓位 × 合成等级系数 × (目标波动率 / 标的 ATR%)

合成等级系数：
  STRONG_PASS = 1.0
  CONDITIONAL_PASS = 0.5
  WEAK_PASS = 0.3
  FAIL = 0（不持仓）
```

### 4.3 最终输出模板

```markdown

**标的**：600036 招商银行
**分析日**：2026-11-13

|---|---|
| 等级 | PASS |
| 5日净流入率 | 1.87% |
| 10日净流入率 | 2.31% |

| 板块排名 | 前3% |
| 结构 | 机构吸筹 |
| 警示 | 20日远低于10日，中期持续性存疑 |

### 技术面
| 维度 | 结果 |
|---|---|
| 趋势状态 | SHORT_REPAIR |
| 趋势折扣 | 0.7 |

### 安全垫
| 维度 | 得分 | 说明 |
|---|---|---|
| 估值(L1) | -0.5 | PE高于行业中位数 |
| 股息(L2) | +1.0 | 4.7% 股息率 |

**STRONG_PASS** — 三维度共振

| 否决项 | 结果 |
|---|---|
| 窗口不足 | 无 |
| 无资金 | 无 |
| 趋势空头 | 无 |

| 无安全垫 | 无 |

**建议仓位**：基础仓位 10% × 1.0 × (3%/3.2%) ≈ 9.4%
```

## 五、取数命令与数据源

### 5.1 数据源优先级

| 数据 | 首选源 | 备用源 | 频率 |
|---|---|---|---|
| 资金流向 | westock `fund flow` | 东方财富 API | 日频（T+0） |
| 行情/K线 | westock `quote` / `technical` | 腾讯行情 API | 日频（T+0） |
| 筹码分布 | westock `chip` | — | 日频（T+0） |
| 板块排行 | westock `sector ranking` | — | 日频（T+0） |
| PE/股息率 | 财报公告 + westock | 新浪/东方财富 | 季频 |
| 一致预期 | 研报汇总 | — | 月频 |

### 5.2 手动取数命令

```bash
# 资金面
westock fund flow 600036  --date 2026-11-13        # 个股资金四层
westock sector ranking --type mainNetInflow          # 板块资金排行
westock sector constituent <sector_code>              # 板块成分股

# 技术面
westock quote 600036  --date 2026-11-13              # 行情数据
westock technical 600036 --date 2026-11-13           # 均线/BOLL/RSI/KDJ/ATR

# 安全垫
westock fund flow 600036 --date 2026-11-13           # 用于计算流通市值
westock chip 600036 --date 2026-11-13                # 筹码成本+获利盘
# PE/股息率需从财报或行情接口获取
```

### 5.3 腾讯行情 API 兜底（免费）

```
https://qt.gtimg.cn/q=600036,601398,601288
```

```
v_sh600036="1~招商银行~600036~42.93~42.63~42.50~328445~...~-0.30~-0.70~..."
```

字段索引：0=市场 1=名称 2=代码 3=现价 4=昨收 5=今开 6=成交量(手)
7=外盘 8=内盘 17=最高 18=最低 30=日期时间 31=涨跌额 32=涨跌幅

### 5.4 PIT 校验清单

| 项目 | 校验方式 | 失败处理 |
|---|---|---|
| 资金流 | `MainNetFlow == JumboNetFlow + BlockNetFlow` | 标记 `R0`，结论待确认 |
| 财报 PE | 以公告日为准，不以报告期为准 | 标注"数据待更新" |
| 窗口覆盖 | 实际天数 ≥ 窗口×80% | L0 不合格 → INSUFFICIENT_DATA |
| 板块排名 | 成分股数量 > 0 | 取 0 时跳过 L3 |

## 六、禁止清单

| # | 禁止 | 正确做法 |
|---|---|---|
| 1 | 把绝对金额当净流入强度 | 用 `main_net_rate` 消除市值偏差 |
| 2 | "全正"就通过 | 必须过 L2 量级门槛（5d≥1.5%, 10d≥1.0%） |
| 3 | 把"逻辑护城河"当安全垫 | 安全垫只量化下行保护 |
| 4 | 在 BEAR_STRUCTURE 下给通过 | 直接 FAIL，不折价 |
| 5 | MACD 零轴下方金叉直接通过 | 需三重确认，系数最多 0.7 |
| 6 | 远期估值当当期安全垫 | 只用于说明"如果兑现，压力缓解" |
| 7 | 行业特征豁免安全垫底线 | 低股息就是 -1，不因行业特征改变 |
| 8 | 用"跌得少"当托底信号 | 先做行业中性化（减行业中位数） |
| 9 | "试仓1手"不带风险预算 | `仓位 = 风险预算% / (止损距离% × ATR)` |
| 10 | 合成时一个维度过就放行 | 必须三维度都通过（或有明确降级逻辑） |

## 七、已知局限

| 局限 | 影响 | 处理 |
|---|---|---|
| 资金流数据非官方口径 | 不同行情商口径不同 | 只做同源自比，不横向比较 |
| 板块排名依赖申万二级 | 概念板块（算力、机器人）需手动匹配 | 手动 `--sector pt0xxxx` |
| 东方财富 API 经常超时 | `TypeError: fetch failed` | 切换到腾讯行情 API 兜底 |
| 雪球 API 需登录 | HTTP 400/400016 | 不使用，依赖 westock/腾讯 |
| 北向资金数据 | 非实时，需 T+1 | 仅做复盘参考 |
| 一致预期数据 | 获取成本高 | 可选因子，不强制 |
| 交易成本 | 滑点+手续费 0.15%~0.3% | 仓位计算时考虑 |
| 前瞻偏差 | 使用未来数据 | 强制 PIT 校验 |
| 样本外验证 | 阈值可能过拟合 | 阈值需跨周期验证 |

## 八、快速决策树

```
收到股票代码
  │
  ├─ L0 数据校验
  │   ├─ 窗口覆盖 < 80% → INSUFFICIENT_DATA（停止）
  │   └─ 通过 → 继续
  │
  ├─ 资金面接口
  │   ├─ L1 三窗口全正？否 → FAIL
  │   ├─ L2 量级达标？否 → WEAK
  │   ├─ L3 板块排名前10%？否 → WEAK
  │   ├─ L4 结构扣分？是 → PASS→WEAK
  │   └─ 通过 → PASS
  │
  ├─ 技术面接口
  │   ├─ L0 BEAR_STRUCTURE？是 → FAIL
  │   ├─ L1 确认项数=0？是 → FAIL
  │   ├─ L1 确认项数≥2？是 → 系数 0.7+
  │   ├─ L2 超买？是 → 系数 ×0.5
  │   └─ 合成 ≥0.7？是 → PASS；0.4~0.7 → CONDITIONAL_PASS；<0.4 → FAIL
  │
  ├─ 安全垫接口
  │   ├─ L1~L4 总分 ≤ -3 → NO_MARGIN（一票否决）
  │   ├─ 总分 -1~-2 → THIN
  │   ├─ 总分 0~1 → MODERATE
  │   └─ 总分 ≥ 2 → THICK
  │
  └─ 三维度合成
      ├─ 任一否决 → FAIL
      ├─ 全通过且安全垫≥MODERATE → STRONG_PASS
      ├─ 全通过但安全垫=THIN → CONDITIONAL_PASS
      └─ 其他组合 → 降级处理
```

## 九、与"资金结构盯盘"的对比

| 维度 | 资金结构盯盘 | 本技能（资金面接口） |
|---|---|---|
| 粒度 | 个股 S1-S6 状态 | 分层判定 PASS/WEAK/FAIL |
| 核心逻辑 | 特大单/大单/小单方向 | 多窗口净流入率 + 板块排名 |
| 速度 | 快速扫描（适合盘中/盘后批量） | 精确判定（适合深度分析） |
| 适用 | 盯盘、持仓管理、快速筛选 | 选股、建仓决策、风险报告 |
| 互补 | 先用盯盘 S 状态粗筛 | 再用本接口做精细判定 |

**使用建议**：先跑"资金结构盯盘"筛出候选 S1/S2 标的，再用本技能做三维度精细分析。

## 十、与"建仓确认"的关系

| 阶段 | 技能 | 回答 |
|---|---|---|
| **三维度分析** | 本技能 | 这个票值不值得关注？（安全+资金+技术） |
| **建仓确认** | 建仓确认 | 值得关注的票，现在能不能下单？（五验交叉） |

**流程**：本技能给出 `STRONG_PASS` / `CONDITIONAL_PASS` → 送入"建仓确认"五验 → 最终决定是否下单。

两者不是重复，是**串行**。本技能是"看值不值得"，建仓确认是"能不能买"。
